先拆三個誤會

不是變聰明，是被裝上手腳

常見誤會實際情況對應的詞
「AI 變聰明了」被接上工具，從會講變成會做 Agent
「AI 會記得我」預設每次都失憶 Memory
「用哪個都差不多」差在外面那層，不在模型 Harness

正好是今天要講的三個詞。

「AI 變聰明了」：模型有進步，但變化最大的是它被接上了工具和流程，從「會講」變成「會做」。 「AI 會記得我」：預設是每次都失憶。它記得，是因為有人幫它把資料再送一次。 「用哪個都差不多」：同一個模型，放在不同軟體裡表現可以差很多。差在外面那層，不在模型。

五個詞，都在同一間辦公室裡。

（六張卡片可點開定義） 腦袋 LLM：會讀、會想、會寫，但只能輸出文字，碰不到你的電腦。 桌面 Context：他此刻攤開的資料。這一輪看得到的全部，桌子有大小限制。 交接本 Memory：跨天保留的資料。下次上班翻開還在。 鑰匙 Tools：電話、影印機、鑰匙。讓他能真的動到外面的東西。 管家 Harness：辦公室的制度。誰把資料放上桌、准他拿哪把鑰匙、真正去動手的人、做幾輪、何時叫停。 AI Agent：你給目標，它自己拆步驟、用工具、反覆做，直到完成或碰到停點。

M1 · 關係圖

中間那個迴圈，就是 Agent 的全部

想 → 用工具 → 看結果 → 再想。

中間這個迴圈就是 Agent 的全部：想 → 用工具 → 看結果 → 再想。學術上叫 ReAct（Reasoning + Acting）。 外框是 Harness：決定桌面放什麼、准用哪些工具、做幾輪、何時停。 紅色箭頭兩條：經 MCP／連接器真的動到外面的東西；不用工具時直接輸出，停下來交給你驗收。

💭「AI 忘記我剛剛說的話」，是哪一邊的問題？

先想：「AI 忘記我剛剛說的話」，是 Context 還是 Memory 的問題？ Context 桌面：系統 ＋ 你這次貼的內容，只在這次對話；關掉視窗全部消失。 Memory 交接本：你事先寫的，或 AI 自己記下的；跨對話保留，只在需要時載入，相對便宜。校園實例：「我是屏北高中生活科技老師」這句設定。 另外，「聊久了變笨」只講了一半 —— 另一半是越長越貴：每問一句整張桌子都要重送（用 token 計價，中文更耗），而老師多半用免費額度。

M1 · 本課重點

大腦與管家

LLM｜大腦

推理層

思考、生成、決策。
產出只有文字，碰不到你的電腦。

HARNESS｜管家

執行與控制層

執行工具、讀寫檔案、安全控管。
能動你的電腦，權限由它決定。

真正把指令跑下去的，是 Harness。

LLM 大腦：模型本身，API 背後那顆算力與大腦。負責邏輯思考、語言生成、決策。產出只有文字 —— 包含「我要執行這個指令」這句話。碰不到你的電腦，完全不能。 Harness 管家：圍繞模型外圍的工程系統與介面外殼。① 工具執行 ② 檔案系統互動 ③ 畫面渲染與格式化 ④ 安全與邊界控管 ⑤ 錯誤處理與重試。能動你的電腦，而且權限由它決定。 關鍵觀念：LLM 說「請執行這個指令」，這句話本身也只是一段文字。真正打開終端機把指令跑下去的，是 Harness。 第 ⑤ 項會讓你看到紅字 —— 那是它在自己修，不要急著按中斷。

「在我電腦上跑」不等於「資料沒離開我的電腦」。

「它能直接在你電腦上動手」這句話對。但它很容易被聽成另一件事 —— 「所以我的檔案沒有上傳，不會有個資問題」。這個推論是錯的。 「它在我電腦上跑」不等於「資料沒有離開我的電腦」。 這就是 M4 第 2 條硬規則真正要防的事 —— 不是防你按上傳鍵，是防你以為自己沒有上傳。

↻　看到結果，回到 ①

決定改什麼的是 AI，真的去改的是一段普通程式。

① LLM 產生指令：純文字，動不了任何東西。 ② 傳給 Harness：管家接單。 ③ Harness 執行：在系統真的跑，並把結果回傳。LLM 看到結果，決定下一步，回到 ①。 所以「AI 幫我改了檔案」這句話其實不準確 —— 決定改什麼的是 AI，真的去改的是一段普通程式。

校園版白話

同一位代課老師，

外框的影響力，不輸模型本身。

管家（Harness）決定的五件事：這一輪把哪些資料放上桌（Context 管理）、准它用哪些工具不准用哪些、跑幾輪什麼時候停、產出要不要先驗證、哪些動作一定要人按同意。 業界共識：外框的影響力不輸模型本身。同一個模型換一套外框，結果可以差很多。 校園版白話：同一位優秀代課老師，放到制度清楚的學校能幫上大忙；放到沒人交代、沒有鑰匙、也沒人驗收的學校，就只能坐在辦公室寫講義。

M1 · 板書用

LLM 是大腦；
Harness 是讓它能安全動手的外殼。

💭 網頁版聊天室，算不算 Harness？

完整板書：LLM 是 API 背後純粹的算力與大腦；Harness 是讓這份能力能被安全控制、執行命令、工程化應用的實體外殼。 提問：那我們平常用的網頁版聊天室，算不算 Harness？—— 算，只是功能較少的一種。

等一下收尾會提到「技能（Skill）」。它不是新能力，是一份純文字的說明書。 流程：你提到觸發詞（例如「幫我出題」）→ Harness 載入說明書、放上 Context 桌面 → LLM 照著做，該用工具時用、該停時停。 「技能是一段程式，我不會寫」：它是純文字。你會把流程寫清楚就會寫技能。 「技能是另一個更強的模型」：同一顆腦袋。差別只在桌上多了一份說明書。 「技能寫好就會一直待命」：要被觸發才載入。沒講到關鍵字，它不會自己拿出來。

你遲早會聽到「裝一個 MCP 就能連 Google」。它不是新的 AI，是 Agent 和外部服務之間的轉接頭。 原廠內建的叫「內建連接器」，別人或自己做的叫 MCP。 「MCP 是另一個 AI」：它不會想，只是轉接頭。想事情的還是同一顆腦袋。 「裝越多，它越厲害」：每個轉接頭的使用說明都佔桌面。裝太多，桌面先被佔滿。 「接上了，它就什麼都能動」：接得上是一回事，准它動多少是另一回事。通道和權限是兩件事（A6）。 「有人分享，裝來用就好」：轉接頭在你電腦上跑、經手你的資料。來路不明的不要裝（M4）。 轉接頭比喻改編自三師爸 Sense Bar EP04。

只有兩個範圍：全域跟著「人」走，專案跟著「資料夾」走。 全域有兩種放法，內容可以一樣，差別只在工具： ・聊天 App（網頁版、手機版）→ 設定裡的「自訂指示／個人偏好」欄，存在雲端帳號。今天寫的四行放這裡。 ・在電腦上跑的 Agent 工具 → 家目錄裡的一個檔案，Claude Code 是 ~/.claude/CLAUDE.md。兩邊一般不互通，網頁版填的偏好，Agent 工具讀不到。 專案 → 專案資料夾裡的藍圖檔，只有在那個資料夾工作時才讀。速成版的「專案初始化」就是在寫它。 讀的順序是全域先、專案後；兩邊衝突時以專案為準，因為寫得比較具體。 例子（八年級數學老師）：「我是數學老師、先講結論」寫全域；「數學式一律用 OMML」到哪都要，也寫全域；「八上第一次段考範圍 1-1 到 2-3、配分 60／40」只有這件事要，寫專案。 檔名小提醒：Claude Code 自動讀 CLAUDE.md；Codex、OpenCode 等工具讀 AGENTS.md。只有 AGENTS.md 時，在同一個資料夾放一個 CLAUDE.md，內容寫一行 @AGENTS.md 就能兩邊共用。

M2 · 四行模板

四行就夠，寫長反而失效

第 1 行　我是＿＿＿，主要工作是＿＿＿。
第 2 行　回答用繁體中文，先講結論，條列為主。
第 3 行　我不熟＿＿＿，遇到請多解釋一句。
第 4 行　資訊不足時，先給草稿、缺的地方標成［待填］，不要先反問我。

第 4 行最實用：它先給八成，你改二成。

⚠️ 超過 300 字就開始稀釋。

第 4 行是全課最實用的一行。AI 預設「先問清楚再做」，因為它怕做白工。你只要明講「先做再說」，它就會先給你八成，你改二成。 寫太長會失效：超過 300 字就開始稀釋，四行剛好。

今天學的四問，就是說明書的骨架。

它不是程式，是用純文字寫清楚的一份 SOP。你不需要會寫程式，只需要會把流程寫清楚 —— 而這正是老師最擅長的事。 ① 技能名稱：給它一個好叫的名字。② 觸發條件：什麼時候該做、什麼時候不該觸發。 ③ 流程步驟：從收到指令到產出成品。④ 規則：哪裡不准碰、不得超出範圍。 ⑤ 輸出格式：成品長什麼樣、有哪些欄位。⑥ 驗收檢查點：跑完要主動回報哪幾件可核對的事實。 寫技能不是重新想一遍，是把已經講清楚的東西搬進去。

重點在「能改」，不在「能用」

LEVEL 3

能設計

為校內業務設計流程

會貼設定的人很多，看得出錯的人很少。

LEVEL 1 能用：寫得出四行設定，用四問交辦一件單步任務。 LEVEL 2 能改：看得出產出哪裡不對，能修正指令重跑。 LEVEL 3 能設計：能為一項校內業務設計流程，含邊界與人工確認點。 對應 UNESCO 教師 AI 能力框架 Acquire / Deepen / Create。 今天沒教、但你遲早要碰的：技能（做第三次同一件事時）、專案藍圖、連接器、Agent 工具與終端機。

收尾 · 決定你長期省不省力的分野

「能改」改的是指令，不是成品

手改成品回頭改指令
你做的自己修好指出位置，要它重跑
這次拿到對的東西拿到對的東西
下一次再錯一次它記得這個要求
累積下來你變成校稿工你變成設計者

手改成品只救這一次，改指令才救下一次。

決定你長期省不省力的分野。 手改成品：自己動手把錯的地方修好；下一次再錯一次、再改一次；累積下來你變成 AI 的校稿工。 回頭改指令：指出問題位置，要它重跑；下一次它記得這個要求（寫進設定或技能更穩）；累積下來你變成流程的設計者。 而當你發現同一個修正講了第三遍 —— 那句話就該寫進設定，或者整套流程該寫成技能。這就是「能改」通往「能設計」的路。

收尾 · 老實話

第一次一定會不順

講述版

聽懂不等於會用。
回去挑一件真實業務試一次。

實作版

卡住先回頭看四問，
八成是漏了第三或第四問。

講述版：今天沒有動手。概念聽懂不等於會用 —— 回去請至少挑一件真實業務試一次。第一次一定會不順，那是正常的。 實作版：今天動手的是最單純的情境。回到自己的業務上一定會卡。卡住時先回頭看四問 —— 八成是漏了其中一問，而且通常是第三問或第四問。

帶走這三句就夠

講第三次的話，就該寫進設定。
做第三次的事，就該寫成技能。
AI 沒有責任，你有。
