CHAT AI VS AGENT

Chat AI 回答你，Agent 幫你做完

Chat AI（聊天）

你問
→
它回文字
→
你自己貼
  • 只輸出文字，碰不到你的檔案
  • 你是操作者：複製、貼上、存檔
  • 關掉視窗，就忘了

Agent（做事）

給目標
→
拆步驟
→
用工具
→
看結果
  • 能讀寫你指定的資料夾，檔案直接存好
  • 你是驗收者：看成品對不對
  • 有藍圖和交接檔，下次接得上

比喻：問路 vs 叫車——問路你自己走；叫車它自己轉彎，但你要說得出目的地。

核心一句：聊天 AI 是「講」，Agent 是「做」。兩者背後都是同一類語言模型，差別在外面接了什麼。

Agent 的中間是一個迴圈：想 → 用工具 → 看結果 → 再想，直到做完或碰到停點。

提醒：Agent 不是每次走一模一樣的步驟，同一句話這次先做 A、下次先做 B 都正常；要驗的是成品，不是過程。

THE PARTS

Agent＝一位聰明、但每天上班都失憶的工讀生

技能不是新能力，只是放在桌上的一份 SOP 說明書。

用這張圖把五個詞一次對起來：LLM＝腦袋、Context＝桌面、Memory＝交接本、Tools＝手上的工具、Harness＝管家兼制度；Agent＝全部合起來。

學生最容易混的是 Context 與 Memory：Context 只在這次對話，關掉就沒；Memory（藍圖、交接檔）是寫在檔案裡，下次還在。

Codex 就是這裡的 Harness，不是 LLM。換一個模型，Codex 還是 Codex。

LLM VS HARNESS

大腦負責想，管家負責做

LLM｜大腦

  • 產出的只有文字，連「請執行這個指令」也只是文字
  • 不在你的電腦上，在遠端
  • 你的點數，就是用在它的運算上

Harness｜管家（Codex）

  • 真的讀檔、寫檔、跑工具、畫畫面
  • 決定它能碰哪些資料夾、哪些動作要先問你
  • 工具失敗時，把錯誤丟回給大腦重想

注意：管家在你的電腦上動手，但想事情是在外面想的。它讀到的內容會被送出去——不要讓它讀個人資料或密碼。

一句話：LLM 是 API 背後的算力與大腦；Harness 是讓這份能力能被安全控制、能真正動手的外殼。

常見誤會：「它在我電腦上跑，所以沒有上傳。」錯。它先在你電腦上把檔案內容讀出來，再送到模型那端。「在我電腦上跑」不等於「資料沒離開我的電腦」。

紅字報錯不用急著中斷：這是管家把錯誤丟回去讓大腦重想，正常運作。反而要小心「失敗了還說完成」，所以最後一定自己驗收。

CONTEXT

桌面會被塞滿：每問一句，整桌重送一次

越長越慢、越貴：你的點數用得更快。

聊久了會變笨：桌面被舊內容擠滿。

怎麼辦：一次只做一件事、換題目就開新任務、重要規則寫進藍圖。

Context 與 Memory 對照：Context＝桌面，只在這次對話、有上限、每輪整份重送；Memory＝交接本，跨對話保留。

「AI 忘記我剛剛說的話」多半是 Context 問題（桌面被擠爆），不是交接本丟了。

token 可理解為「字數的計價單位」，中文通常比英文更耗。這就是為什麼我們要在上課前先領「點數」，用量是共用的、有限的。

所以開新任務不只是讓它變聰明，也是為了省點數。

做好了，但檔案只在你電腦裡，只有你打得開。同事要、學生要看，就得給一個網址 —— 這就是部署。 註冊只做四件事：開 github.com 按 Sign up、填資料、收驗證碼、記下使用者名稱。 使用者名稱會變成網址的一部分（https://名稱.github.io/…），所以用英文或數字，不要用中文；要改很麻煩。 免費方案就夠用：公開的 repo 和 GitHub Pages 都不收費。 最下面那句是法遵底線（對應 A8-D2-2）：repo 公開就是全世界都看得到，學生姓名、班級、座號一律換掉再上傳。 課後自己做的話，把左邊四步照順序做完就好，其餘交給 AI。

上線不算完，打得開才算。三項驗收：無痕視窗、手機、貼給隔壁同事。 為什麼要無痕？因為你自己的瀏覽器可能還登入著 GitHub，看到的是「只有你看得到」的版本。 作品牆是課後作業、自由參加，沒有期限：把 GitHub Pages 網址貼上去，系統會自動截圖並帶入標題，你勾一張當封面就送出。 只有上傳要通關碼，看作品不用。通關碼現場公布，也會放在散場講義。 作品牆上可以看同一題別人怎麼做，也可以直接拿回自己班上用。

→

合作學校要寫的，大多在表格裡：課程表、活動表、研習表、經費表。

國教署計畫格式不一：高優計畫幾乎全是表格；新興科技聯盟計畫是「段落＋表格」。但仔細看合作學校版，計畫目標、摘要那些段落是中心學校寫的，我們要寫的主體其實在四張表裡。 為什麼不叫它直接改 Word？計畫書有合併儲存格、核章欄、看不見的格式，程式寫回去常常把排版弄壞；而且送出去的文件是你核章負責。所以分工是：它寫「修訂對照表」，你貼回 Word。 真正省力的是第 5 步：同一件事在課程表、活動表、研習表、經費說明出現四次，人工很容易漏改一處，AI 不會累。 讀 Word 用 ppsh-office-reader（技能包已改成 Word 用 anydoc，合併儲存格不會錯欄）；要它產出新的 Word 草稿就用 ppsh-word-writer。 中心學校寫的段落不要自己改，請它另列「建議中心學校調整」。

Q1 · 撰寫計畫｜換成你的檔名與重點

一段話：先盤點，再改寫

貼給你的 AI Agent · 整段複製

請用 ppsh-office-reader 讀「115新興科技計畫書.docx」，這是我們學校去年的計畫。 116 學年度要把「雷射切割機教學」列為重點：去年已編列雷射雕刻機，今年不再買；新開一門高一雷切課程，結合 AI 協作設計；3D 列印份量減少；每學期 10 萬元、資本門 3 萬元不變。 不要改原檔。修改內容用「修訂對照表」給我（位置｜原文｜修改後｜理由），我自己貼回 Word。 同一件事出現在課程表、活動表、研習表、經費表，要一起改；金額改了要重算；沒把握的事標「待確認」，不要自己編。 先只列出這個重點會牽動哪些位置，等我確認再改寫。

做什麼、用什麼、不做什麼、驗什麼 —— 四問都在裡面

這段是實際案例：屏北 115 學年度新興科技聯盟計畫，116 學年度想以雷切教學為重點。換成你的計畫時，只要改三個地方：檔名、今年的重點、經費上限。 逐句對交辦四問：第一句是「用什麼」；第二句是「做什麼」；「不要改原檔」「不要自己編」是「不做什麼」；「金額重算、要一起改、標待確認」是「驗什麼」。 最後一句最重要：先盤點、停下來。它列出來的位置你看過、刪掉不要的，再叫它寫對照表。一次叫它全部改完，錯了你很難找。 如果有今年的徵件須知，一起放進專案資料夾，並在第一句加上「對照今年徵件須知」——次主題編號、必填項目常常每年改。

Q1 · 實例：115 → 116，雷切當重點

它該替你抓出來的事

今年的重點牽動

01課程表：雷切不是積層製造，次主題要重選
02活動、研習表：名稱裡的「3D 列印」要一起改
03經費表：設備去年買過，設備費改列別項
04不能把 115 全部換成 116

舊計畫常見的漏洞

01編了設備，卻沒有對應的課程
02同一場活動，兩處名稱不一樣
03徵件要求的項目漏寫

左邊是「今年的重點會牽動哪裡」，好的 Agent 盤點時應該列得出來： 01 雷射切割是減法加工，不屬於「3-2 積層製造」（那是 3D 列印），要對照徵件須知重選次主題 —— 這種專業判斷要你確認，不能讓它沿用去年的。 02 去年的工作坊、成果展名稱都叫「AI×3D列印」，改重點就要一起改。 03 去年第 2 學期已編列雷射雕刻機，今年設備費要改列其他項目（例如排煙設備，待確認）；材料費說明改成木板、壓克力。 04 年度陷阱：去年的計畫裡本來就有「116 年 1 月 31 日」這種日期，全部取代成 116 會變成錯的日期，要逐一處理。 右邊是用 AI 幫舊計畫「健檢」時，實際抓到的幾類問題（不點名哪一份）：有編設備卻沒有課程對應（審查委員會問買來做什麼）；同一場參訪在活動表和經費表名稱不同；徵件須知要求「參與聯盟外研習至少 6 場」卻沒規劃；聯絡人職務已經異動。 經費小計可以叫它驗算，但貼回 Word 之後、送出核章之前，數字和人名你還是要自己看一次。

Agent 看不懂畫面，但讀得懂字幕：有了 SRT，它就知道每一句話在第幾秒，可以照內容挑段落、算時間點。 ffmpeg 是剪影片、轉檔、上字幕的指令工具，動手 ① 裝技能包時已經一起裝好（口白影片要用）。你不用學指令，它來下。 「等我確認」很重要：挑哪幾段是你的判斷。燒進畫面的字幕改不掉，所以 SRT 要先校對；想保留修改空間，就叫它「字幕另外放、不要燒進畫面」。 中文字幕要指定字型，不然可能變成方框。 學生入鏡的影片：剪完要公開前，確認有沒有不該出現的臉、名牌、聲音。 （本頁流程待研習前實機測一次。）
